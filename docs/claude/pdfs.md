# Book PDFs, scans without a text layer, entry boxes

Part of the project's notes: `CLAUDE.md` is the short core, loaded in every session, and this file holds one topic. It was moved here from `CLAUDE.md` as it stood on 2026-11-08; new notes on this topic go here.

**Book PDFs** are read by the viewer in 64 KB ranges, but to open a book it reads the page tree and every page object, which in most scans lie all through the file (opening Prva lička read 11 of its 18 MB). After adding a PDF to `website/public/pdfs`, run `python scripts/repack_pdfs.py <file>` (no argument: every PDF that needs it; `--dry-run` to see what each reads to open). It saves the file with object streams and keeps it only if every object, page image and the text layer are unchanged, so positions and entry boxes stay valid.

**Scans without a text layer** are read with Tesseract 5 on this machine (a conda environment in `E:\envs\ocr`, with tessdata_best's `srp`, `srp_latn`, `hrv` and `slv` in `E:\envs\ocr\tessdata_best`; deleting the folder removes it; no scan goes to an online service). `python data-extraction/ocr_scan.py <site pdf> --lang srp [--columns 2 | --split 0.49] [--psm 3] [--pages 1,2]` renders each page of the site's PDF at 300 dpi, cuts it into its columns at the white gutters (or where `--split` says), reads each column word by word and reads again, at 450 dpi, the words it was unsure of (the first reading kept beside the better one), and saves the words with their boxes in the PDF's points to `data-extraction/ocr/<pdf stem>.json` (`--pages` merges into it). The parsers read only that file (`ocr_scan.load`), so they run without the engine. `data-extraction/_ocr_readback.py` reads a name or a word back from the site's names and entries, weighing each reading by how often the site has it and how likely the OCR is to misread a letter so (this type's Ђ read as Б, Т as Г, Ж as К, a Latin look-alike for a Cyrillic letter, a lost caron). What no rule reads is typed from the page image beside the OCR file: `<stem>.scan.json` (a row's fields), `<stem>.lines.json` (a line's text, by its top and left, with a new top or left where the OCR set it elsewhere; an empty text drops a line of specks) and `<stem>.heads.json` (the headings). Read so far: the Nikšićki odred's fallen and heroes, *Teslić u NOB*, the 1. bokeljska's roster and the Lovćenski odred's fallen. The 6. vojvođanska's list of those the brigade thanked (unit 83's book, both copies, PDF pp. 198-202) is an 80-dpi halftone no OCR can read; a better scan would be the VII archive's kutija 1245-A, reg. 22-2/3.

**Entry boxes** (`pdf_x_end`, `pdf_y_end`, and `pdf_x_left` where the box's left edge isn't `pdf_x`) are the box the PDF viewer highlights. `data-extraction/entry_boxes.py` computes them from the PDF text: from the entry start (`pdf_x`/`pdf_y`) down its column until the next known entry, a line that starts a new entry by the book's indentation (hanging, first-line or flush, measured per book and page; in a book that hangs, a page whose lines all start level, and an entry that starts one indent right of its column's starts, are flush, as in 7. crnogorska's unnumbered entries among its numbered ones; in a book that indents first lines, an indented line starts an entry only after a line that ends a sentence and if it doesn't begin in lowercase, since the text layer drops leading dashes, as in 2. vojvođanska's "Čortanovci / — Inđija"), a gap, or the column end. `apply_corrections.py` runs it last, for every unit on the site, so boxes always follow the final positions; they are never taken from corrections (don't set `pdf_y_end` there). Run it alone with `python data-extraction/entry_boxes.py [--brigade N] [--apply]`. Page lines are cached in `data-extraction/.cache/` (gitignored); the first run reads ~2,800 pages (~2 min). Two-column books must be listed in `entry_boxes.TWO_COLUMN` (or `TWO_COLUMN_PAGES` when only some pages are), books with more columns in `MULTI_COLUMN` (the 32. division's four-column roster), and lists that give each soldier one line in `ONE_LINE_ENTRIES` (else a box runs down the column); after adding one, delete its cached pages (`data-extraction/.cache/entry_boxes/<pdf>.json`), which were read as one column. Lists that run the names on in lines (`INLINE_ENTRIES`: `druga-proleterska.pdf`, `12-dalmatinska.pdf`, `11-krajiska-zene.pdf`, `3-banijska.pdf`), 12. vojvođanska's and 7. srpska's rosters of two names a line, and 13. vojvođanska's roster (its columns sit at a different place on every page), keep the boxes their parser gives: around the name's own words, and as `pdf_rects` (one `[left, top, right, bottom]` per line, which the viewer draws each) when a name runs on to the next line or column. The cut-out shown under a record's facts and on the memorial card joins an entry's `pdf_rects`, one under the other (`cropBoxes`, `EntryCrop`; before 2026-11-05 it took the first alone, from the heading's left edge). `STOP_AT_NEXT` ends such a list's boxes above the next entry that starts inside them (`stop_at_next_entry`: the Dalmatinci list's boxes ran a line late, or, where a man's heading was only read later, over whole columns of other men: 264 of 1,454). An entry that runs on to the next page has no box there, so its cut-out stops at the page's end (about 170 in that list). `INLINE_PAGES` does the same for some pages of a PDF whose other pages are boxed as usual (the 19. srpska's staffs after its roster).
