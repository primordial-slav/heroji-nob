You are validating OCR-extracted text from WWII Yugoslav Partisan brigade records (fallen soldiers lists).

## Task

For each line of text, determine if it represents exactly ONE soldier entry.

## Input Format

You will receive numbered lines:
```
1. ADAMOVIĆ Petra MILAN, rođ. 1920, s. Korenica...
2. BABIĆ Marka JOVO some text MARIĆ Ive PERO another soldier
3. (nastavak) umro od rana 1943.
```

## Output Format

Return JSON:
```json
{
  "validations": [
    {
      "line_num": 1,
      "is_valid": true,
      "issue_type": "",
      "suggested_fix": ""
    },
    {
      "line_num": 2,
      "is_valid": false,
      "issue_type": "merged_soldiers",
      "suggested_fix": "Split: 'BABIĆ Marka JOVO some text' and 'MARIĆ Ive PERO another soldier'"
    },
    {
      "line_num": 3,
      "is_valid": false,
      "issue_type": "incomplete",
      "suggested_fix": "Merge with previous entry"
    }
  ]
}
```

## Issue Types

- **merged_soldiers** - Two or more soldiers combined in one line
  - Look for: multiple ALL-CAPS surnames, repeated name patterns, "i" (and) between names
  - Example: "MARIĆ Jove PERO i BABIĆ Marka MILAN" = two soldiers

- **incomplete** - Fragment of a soldier entry, needs merging
  - Look for: starts with lowercase, continuation markers, orphaned data
  - Example: "poginuo 1943. kod Kozare" (no name, just death info)

- **garbage** - Non-soldier content
  - Look for: page numbers, headers, book titles, chapter markers
  - Example: "Stranica 45", "SPISAK PALIH BORACA", "---"

- **formatting** - Minor OCR errors that can be corrected
  - Look for: broken words (pogi-nuo), strange characters, obvious typos
  - Example: "ADAMOVIĆ Petra MlLAN" (l instead of I)

## Context

- Serbian/Croatian names follow: LASTNAME Father's_name FIRSTNAME
- Common words: rođ./rođen (born), poginuo (killed), umro (died), s./selo (village)
- Special characters: č, ć, š, ž, đ (may have OCR errors)

## Rules

1. A valid line has ONE clear surname (usually ALL CAPS) and biographical info
2. If unsure, mark as valid - false positives are worse than false negatives
3. For merged_soldiers, try to identify the split point
4. For incomplete, note what it should merge with (previous/next)
